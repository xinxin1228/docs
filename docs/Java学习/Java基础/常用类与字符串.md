# 常用类与字符串

## 概述

> 字符串、包装类、类型转换、BigDecimal,是我写后端业务代码时**每天都要碰**的四样东西。这篇不铺概念,直接上「实际会用到」的 API 速查和踩过的坑。尤其是**类型转换**,一堆 `parseInt`/`valueOf`/`getInteger` 长得像、语义完全不同,搞混就是线上 bug。

## String:不可变与常量池

`String` 一旦创建内容不可变,任何「修改」都返回**新对象**:

```java
String s = "hello";
s = s + " world";   // 原 "hello" 还在,s 指向新对象
```

不可变的好处:线程安全、能放心当 HashMap 的 key、常量池复用。

```java
String a = "hello";                 // 字面量,进字符串常量池
String b = "hello";                 // 复用池里的同一对象
String c = new String("hello");     // 强制在堆上新建
System.out.println(a == b);         // true,池复用
System.out.println(a == c);         // false,不同对象
System.out.println(a.equals(c));    // true,内容比较
```

**规则:字符串比内容一律用 `equals`,别用 `==`。** `==` 比的是引用地址。

## String 常用 API(速查)

```java
str.length();                    // 长度
str.isEmpty();                   // 是否空串
str.charAt(0);                   // 第 0 个字符(越界抛异常)
str.substring(0, 3);             // [0,3),含头不含尾
str.indexOf("x");                // 首次出现的下标,找不到 -1
str.lastIndexOf("x");            // 最后一次出现
str.startsWith("a");             // 前缀
str.endsWith("z");               // 后缀
str.contains("x");               // 是否包含
str.replace("a", "b");           // 替换所有
str.split(",");                  // 按正则分割(注意 . 是特殊字符)
str.trim();                      // 去首尾空白(老)
str.strip();                     // Java 11+,处理更多 Unicode 空白
str.toUpperCase();               // 转大写
str.toLowerCase();               // 转小写
str.equalsIgnoreCase(other);     // 忽略大小写比较
str.join("-", list);             // 用分隔符连接集合
String.format("%d 元", 100);     // 格式化
"hi %s".formatted(name);         // Java 15+ 格式化,更顺眼
```

一个分割的坑:`"a.b".split(".")` 得到**空数组**,因为 `.` 在正则里是「任意字符」,要 `split("\\.")`。另外 `split` 默认丢弃尾部的空串。

## 类型转换(重点中的重点)

这部分 API 长得像、语义差很多,我按「谁转谁」分类记,比按类名记好使。

### 1. 任意类型 → String

核心是 `String.valueOf(...)`,它是**重载方法**,传什么类型编译器自动选对应版本:

```java
String.valueOf(123);            // "123"
String.valueOf(45.67);          // "45.67"
String.valueOf(true);           // "true"
String.valueOf('a');            // "a"
String.valueOf(new Object());   // "java.lang.Object@636be97c"(类名@哈希)

// 其他等价写法
Integer.toString(123);          // 专门转 int
"" + 123;                       // 拼接法,简单但循环里别用(生成中间对象)
```

两个关于 `valueOf` 的坑:

```java
// 坑 1:null 会怎样?
String.valueOf((Object) null);  // "null"(对象重载版安全返回 "null")
String.valueOf(null);           // 抛 NullPointerException!因为编译器把 null 解析到了 valueOf(char[]) 这个重载
// 要安全转 null,用 Objects.toString(x) 或 String.valueOf((Object) x)

// 坑 2:数组不能直接 toString
int[] arr = {1, 2, 3};
arr.toString();                 // "[I@..." 不是 "[1, 2, 3]"
Arrays.toString(arr);           // 正确:"[1, 2, 3]"
```

### 2. String → 基本类型

| 字符串 | 目标类型 | 方法 | 说明 |
|--------|----------|------|------|
| "123" | int | `Integer.parseInt("123")` | 返回基础类型 `int` |
| "123" | Integer | `Integer.valueOf("123")` | 返回包装类,带 -128~127 缓存 |
| "ff" | int | `Integer.parseInt("ff", 16)` | 按 16 进制,得 255 |
| "123" | long | `Long.parseLong("123")` | |
| "1.5" | double | `Double.parseDouble("1.5")` | |
| "1.5" | float | `Float.parseFloat("1.5")` | |
| "12.3" | BigDecimal | `new BigDecimal("12.3")` | 精确,别用 double 构造 |
| "true" | boolean | `Boolean.parseBoolean("true")` | 见下方坑 |

```java
int n1 = Integer.parseInt("123");    // 123
int n2 = Integer.parseInt("ff", 16); // 按十六进制解析,255

boolean b1 = Boolean.parseBoolean("true");   // true
boolean b2 = Boolean.parseBoolean("FALSE");  // false(不区分大小写)
boolean b3 = Boolean.parseBoolean("yes");    // false!不是 "true" 就全是 false,不抛异常
```

`Boolean.parseBoolean` 的坑:**只要不是 `"true"`(忽略大小写),一律返回 `false`,不报错**。别以为传了 "1" 或 "yes" 会得到 true。

`parseInt` 的坑:字符串带空格、空串、非数字,直接抛 `NumberFormatException`:

```java
Integer.parseInt(" 123");  // 抛异常,有前后空格,先 .trim()
Integer.parseInt("");      // 抛异常
Integer.parseInt("abc");   // 抛异常
Integer.parseInt("+123");  // 可以,正号合法
```

### 3. 包装类与基本类型互转(装箱/拆箱)

```java
Integer x = 10;        // 自动装箱,等价 Integer.valueOf(10)
int y = x;             // 自动拆箱,等价 x.intValue()

// parseInt 返回 int,valueOf 返回 Integer
int a = Integer.parseInt("123");   // 基础类型
Integer b = Integer.valueOf("123"); // 包装类
```

`Integer.valueOf` 对 `-128 ~ 127` 有缓存,所以:

```java
Integer i1 = 127, i2 = 127;
System.out.println(i1 == i2);   // true,命中缓存
Integer i3 = 128, i4 = 128;
System.out.println(i3 == i4);   // false,超出缓存,各自 new
```

**包装类比大小/比内容用 `equals`,别用 `==`。**

### 4. 数字转其他进制

```java
Integer.toHexString(255);     // "ff"
Integer.toBinaryString(10);   // "1010"
Integer.toOctalString(8);     // "10"
Integer.toString(255, 16);    // "ff"(指定进制)
Integer.parseInt("ff", 16);   // 255(16 进制转回)
```

### 5. char 与数字

```java
int code = 'A';                    // 65,char 自动转 int(Unicode 码点)
char c = (char) 65;                // 'A',int 转 char 要强转
int digit = '5' - '0';             // 5,字符数字转数值的经典技巧
int digit2 = Character.getNumericValue('5');  // 5,更规范
Character.digit('f', 16);          // 15,任意进制字符转数值
```

注意 `char` 是 UTF-16 的 2 字节,emoji 这类字符会占**两个 char**(代理对),按字符遍历时 `charAt` 可能拆散。

## 类型转换里最容易踩的坑:Integer.getInteger

```java
// ❌ 很多人以为这是「字符串转整数」,大错特错
Integer.getInteger("123");

// 它真实含义:读取名为 "123" 的「系统属性」,返回该属性的整数值
// 相当于 Integer.getInteger(nm, null),没这个属性就返回 null
```

**`Integer.getInteger(String)` 不是解析字符串,而是读 JVM 系统属性**(`System.getProperty` 的整数版)。它只在 `-Dkey=value` 启动参数、或 `System.setProperty` 设过对应属性时才返回非 null。

```java
System.setProperty("my.count", "42");
Integer.getInteger("my.count");   // 42,读的是属性
Integer.getInteger("123");        // null,因为没有名为 "123" 的属性
```

想「把字符串转整数」,正确用 `Integer.parseInt("123")` 或 `Integer.valueOf("123")`。**这个坑和 `String.valueOf(null)` 的 NPE,是我见过后端新人最常踩的两个类型转换 bug。**

## StringBuilder / StringBuffer

循环里频繁拼接,别用 `+`(每次创建新对象):

```java
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) sb.append(i).append(",");
String result = sb.toString();
```

- `StringBuilder`:线程不安全,快,日常首选
- `StringBuffer`:线程安全(方法加锁),慢,基本不用

## BigDecimal:金额必用

`double`/`float` 二进制表示不了精确的十进制小数(和 JS 的 `0.1 + 0.2` 同源):

```java
System.out.println(0.1 + 0.2);   // 0.30000000000000004
```

金额/精度场景必须用 `BigDecimal`,而且**用字符串构造**,别用 double:

```java
BigDecimal price = new BigDecimal("19.90");   // ✅ 字符串构造
BigDecimal bad = new BigDecimal(19.90);       // ❌ double 构造,还是带误差

BigDecimal total = price.multiply(new BigDecimal("3"))
                        .setScale(2, RoundingMode.HALF_UP);  // 59.70,四舍五入保留 2 位
```

比大小用 `compareTo`,别用 `equals`(`equals` 还比较 scale,`1.0` 和 `1.00` 不相等):

```java
new BigDecimal("1.0").equals(new BigDecimal("1.00"));   // false
new BigDecimal("1.0").compareTo(new BigDecimal("1.00")); // 0,相等
```

## 示例

```java
import java.math.BigDecimal;
import java.math.RoundingMode;
import java.util.Arrays;

public class ConvertDemo {
    public static void main(String[] args) {
        // 1. 字符串转数字
        int age = Integer.parseInt("28");
        double price = Double.parseDouble("19.9");

        // 2. 数字转字符串
        String s1 = String.valueOf(age);        // "28"
        String s2 = Integer.toString(age);      // "28"

        // 3. 金额计算
        BigDecimal total = new BigDecimal("19.9")
                .multiply(new BigDecimal("3"))
                .setScale(2, RoundingMode.HALF_UP);
        System.out.println("应付 " + total + " 元");   // 应付 59.70 元

        // 4. 数组转字符串
        System.out.println(Arrays.toString(new int[]{1, 2, 3}));  // [1, 2, 3]

        // 5. 安全解析(带默认值,不抛异常)
        int n = parseOrDefault("abc", 0);        // 0
        System.out.println(n);
    }

    static int parseOrDefault(String s, int def) {
        try { return Integer.parseInt(s); }
        catch (NumberFormatException e) { return def; }
    }
}
```

## 常见问题与坑

- **`Integer.getInteger` 误当字符串转整数**:它读系统属性,不是解析字符串,转整数用 `parseInt`/`valueOf`
- **`String.valueOf(null)` 抛 NPE**:重载解析到 `valueOf(char[])`,安全写法 `String.valueOf((Object) null)` 或 `Objects.toString(x)`
- **循环里 `+` 拼接**:改成 `StringBuilder`
- **`split(".")` 空结果**:`.` 是正则特殊字符,要 `split("\\.")`
- **包装类 `==` 比较**:超出 -128~127 缓存范围就比地址了,用 `equals`
- **`parseInt` 对空格/空串抛异常**:先 `trim()`,不确定就 try-catch 或写个带默认值的 `parseOrDefault`
- **BigDecimal 用 double 构造**:仍带精度误差,一定用字符串构造
