# 异常处理

## 概述

> Java 异常体系:`Throwable` 下的 `Error`/`Exception`、受检异常与非受检异常、`try-catch-finally` 与 `try-with-resources`、自定义异常与最佳实践。后端开发中异常处理直接决定接口健壮性与可排查性。

## 核心知识点

### 异常层次

```
Throwable
├── Error(致命错误,程序无法处理):OOM、StackOverflowError
└── Exception(可处理)
    ├── RuntimeException(非受检,编译期不强制):NPE、IndexOutOfBounds
    └── 其他(受检 checked,编译期强制处理):IOException、SQLException
```

- **受检异常(checked)**:必须 `try-catch` 或 `throws` 声明,否则编译不通过
- **非受检(unchecked, RuntimeException)**:编译器不强制,运行时抛出,通常是 bug 或逻辑错误

### try-catch-finally

```java
try {
    int r = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("除零了: " + e.getMessage());
} catch (RuntimeException e) {          // 多个 catch,先具体后宽泛
    e.printStackTrace();
} finally {
    System.out.println("无论如何都执行");   // 释放资源
}
```

- **多 catch**:Java 7+ 可合并 `catch (AException | BException e)`
- **finally 的坑**:`finally` 里有 `return` 会覆盖 `try` 的返回值;`finally` 在 `System.exit()` 时不执行

### try-with-resources(推荐)

自动关闭实现了 `AutoCloseable` 的资源,无需手动 `finally`:

```java
// 传统写法:容易忘 close
BufferedReader br = new BufferedReader(new FileReader("a.txt"));
try {
    String line = br.readLine();
} finally {
    br.close();
}

// try-with-resources:自动关闭,代码更清爽
try (BufferedReader br = new BufferedReader(new FileReader("a.txt"))) {
    String line = br.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
```

### throw 与 throws

```java
// throws:声明该方法可能抛出异常,交给调用方处理
public void read() throws IOException { ... }

// throw:主动抛出一个异常
public void check(int age) {
    if (age < 0) throw new IllegalArgumentException("年龄不能为负");
}
```

### 自定义异常

```java
public class BizException extends RuntimeException {
    private final int code;
    public BizException(int code, String msg) {
        super(msg);
        this.code = code;
    }
    public int getCode() { return code; }
}
```

业务异常通常继承 `RuntimeException`(非受检),配合全局异常处理器统一返回错误结构(见 Spring 生态章节)。

## 示例

```java
public class ExceptionDemo {
    static int divide(int a, int b) {
        if (b == 0) throw new IllegalArgumentException("除数不能为 0");
        return a / b;
    }

    public static void main(String[] args) {
        try {
            System.out.println(divide(10, 0));
        } catch (IllegalArgumentException e) {
            System.out.println("参数错误: " + e.getMessage());
        } finally {
            System.out.println("清理工作");
        }
    }
}
```

## 常见问题与坑

- **`catch (Exception e)` 吞异常**:catch 了却什么都不做(空块)是最坏实践,要么处理、要么记录、要么重新抛出
- **捕获过于宽泛**:先捕获具体异常再捕获父类,否则具体异常永远进不到自己的 catch
- **把异常当控制流**:异常开销大,不要用抛异常做正常分支判断
- **finally 里 return**:会吞掉 try 中的返回值和异常
- **受检异常的滥用**:把不必要的受检异常一直 `throws` 到最顶层,维护成本高;业务层多用非受检 + 全局处理
- **NPE 定位**:Java 14+ 有 Helpful NullPointerException,会在报错里指明「哪个引用为 null」,注意看异常信息
