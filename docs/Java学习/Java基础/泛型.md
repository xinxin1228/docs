# 泛型

## 概述

> 泛型(Generics)让类/接口/方法在**编译期**约束类型,把「运行时才暴露的 ClassCastException」提前到编译期。核心概念:类型参数、类型擦除、通配符与 PECS 原则。理解泛型是读懂集合源码和 Spring 源码的基础。

## 核心知识点

### 为什么需要泛型

```java
// 没有泛型(Java 5 之前):List 里塞什么都行,取出要强转
List list = new ArrayList();
list.add("hello");
String s = (String) list.get(0);   // 强转,类型错则运行时报错

// 有泛型:编译期就保证类型安全
List<String> list2 = new ArrayList<>();
list2.add("hello");
String s2 = list2.get(0);          // 无需强转,不会类型错
```

### 泛型类 / 接口 / 方法

```java
// 泛型类:类型参数 T 在类名后
public class Box<T> {
    private T value;
    public void set(T v) { value = v; }
    public T get() { return value; }
}
Box<String> box = new Box<>();
box.set("hi");
String v = box.get();

// 泛型接口:集合框架大量使用,如 List<E>、Map<K,V>

// 泛型方法:类型参数在返回类型前
public static <T> T first(List<T> list) {
    return list.isEmpty() ? null : list.get(0);
}
```

### 类型擦除

泛型信息**只在编译期存在**,编译后擦除为原始类型(默认 `Object`,有界则擦除到上界):

```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
// 编译后两者都是 ArrayList,泛型被擦除
System.out.println(a.getClass() == b.getClass());  // true
```

擦除的后果:不能 `new T()`、不能 `T[] arr = new T[10]`、不能用基本类型当类型参数(`List<int>` 非法,要用 `List<Integer>`)、`instanceof` 不能带具体类型参数。

### 通配符与 PECS

```java
// 上界通配符 ? extends T:只能读(T 的子类),不能写
void print(List<? extends Number> nums) {
    for (Number n : nums) System.out.println(n);
    // nums.add(1);   // 编译错误,无法确定具体类型
}

// 下界通配符 ? super T:只能写(T 的父类),读只能读 Object
void add(List<? super Integer> list) {
    list.add(1);       // 可以
    // Integer x = list.get(0);  // 编译错误,只能 Object
}
```

**PECS 口诀**:Producer Extends(生产数据用 extends,只能读)、Consumer Super(消费数据用 super,只能写)。

## 示例

```java
public class GenericsDemo {
    // 通配符:接受任意类型的 List,只读
    static double sum(List<? extends Number> nums) {
        double total = 0;
        for (Number n : nums) total += n.doubleValue();
        return total;
    }

    public static void main(String[] args) {
        List<Integer> ints = List.of(1, 2, 3);
        List<Double> doubles = List.of(1.5, 2.5);
        System.out.println(sum(ints));     // 6.0
        System.out.println(sum(doubles));  // 4.0
    }
}
```

### 案例:泛型 DAO 基类消除重复 CRUD

```java
// 一个泛型接口服务所有实体,主键类型也可不同
public interface BaseDao<T, ID> {
    T findById(ID id);
    List<T> findAll();
    ID save(T entity);
}

public class UserDao implements BaseDao<User, Long> {
    @Override public User findById(Long id) { /* 查库 */ return null; }
    @Override public List<User> findAll() { return List.of(); }
    @Override public Long save(User entity) { return 1L; }
}

public class OrderDao implements BaseDao<Order, String> {   // 主键类型换成了 String
    @Override public Order findById(String id) { return null; }
    @Override public List<Order> findAll() { return List.of(); }
    @Override public String save(Order entity) { return "id-1"; }
}
```

这正是 Spring Data JPA 的 `JpaRepository<T, ID>` 背后的思路:泛型让一个接口复用所有实体,消除海量重复的 CRUD 代码。

## 常见问题与坑

- **泛型不支持基本类型**:`List<int>` 非法,用包装类 `List<Integer>`
- **擦除导致的重载冲突**:`void f(List<String>)` 和 `void f(List<Integer>)` 擦除后签名相同,不能共存
- **`List<String>` 不是 `List<Object>` 的子类**:泛型不可协变,想通用用通配符 `List<?>`
- **在静态方法用类的类型参数**:静态方法无法访问类的类型参数,要自己声明 `<T>`
- **`? extends` 不能写**:记不住就用 PECS 口诀
- **原始类型(裸 List)**:不写泛型参数会得到编译警告,且失去类型安全
