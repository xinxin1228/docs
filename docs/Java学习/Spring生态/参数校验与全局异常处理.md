# 参数校验与全局异常处理

## 概述

> 后端接口的「守门员」:用 Bean Validation 做入参校验,用 `@ControllerAdvice` + `@ExceptionHandler` 统一捕获异常并返回规范错误结构。这是企业级接口健壮性的标配,能大幅减少重复的 `if` 判空。

## 核心知识点

### Bean Validation 注解

`spring-boot-starter-validation` 引入 `jakarta.validation` 的注解:

| 注解 | 校验 |
|------|------|
| `@NotNull` | 非 null |
| `@NotBlank` | 非 null 且去除空白后非空(字符串) |
| `@NotEmpty` | 非 null 且非空(字符串/集合) |
| `@Size(min, max)` | 长度/元素数范围 |
| `@Min` / `@Max` | 数值范围 |
| `@Email` | 邮箱格式 |
| `@Pattern(regexp)` | 正则匹配 |

```java
public class UserDto {
    @NotBlank(message = "用户名不能为空")
    @Size(min = 2, max = 20, message = "用户名长度 2-20")
    private String username;

    @NotBlank(message = "邮箱不能为空")
    @Email(message = "邮箱格式不正确")
    private String email;

    @Min(value = 18, message = "年龄需满 18 岁")
    private Integer age;
}
```

Controller 用 `@Valid` 触发校验(Spring Boot 3 用 `jakarta.validation.Valid`):

```java
@PostMapping
public Result<Void> create(@Valid @RequestBody UserDto dto) { ... }
```

### 分组校验(不同场景不同规则)

```java
public interface Create {}
public interface Update {}

public class UserDto {
    @NotNull(groups = Update.class, message = "id 不能为空")   // 仅更新时校验
    private Long id;
    @NotBlank(groups = {Create.class, Update.class})
    private String username;
}

// 只校验 Create 组
public Result<Void> create(@Validated(UserDto.Create.class) @RequestBody UserDto dto) { ... }
```

### 全局异常处理

用 `@RestControllerAdvice` 统一拦截,返回统一结构:

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 参数校验失败
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .collect(Collectors.joining("; "));
        return Result.error(400, msg);
    }

    // 自定义业务异常
    @ExceptionHandler(BizException.class)
    public Result<Void> handleBiz(BizException e) {
        return Result.error(e.getCode(), e.getMessage());
    }

    // 兜底异常
    @ExceptionHandler(Exception.class)
    public Result<Void> handleOther(Exception e) {
        log.error("系统异常", e);   // 记录堆栈,别吞
        return Result.error(500, "系统繁忙,请稍后重试");
    }
}
```

### 自定义业务异常 + 统一响应

```java
// 统一响应结构
public record Result<T>(int code, String message, T data) {
    public static <T> Result<T> ok(T data) { return new Result<>(0, "success", data); }
    public static <T> Result<T> error(int code, String msg) { return new Result<>(code, msg, null); }
}

// 业务异常
public class BizException extends RuntimeException {
    private final int code;
    public BizException(int code, String message) { super(message); this.code = code; }
    public int getCode() { return code; }
}
```

### 校验失败的两条路径

- **`@RequestBody` + `@Valid`**:失败抛 `MethodArgumentNotValidException`(进上面的 handler)
- **`@RequestParam`/`@PathVariable` + 类上 `@Validated`**:失败抛 `ConstraintViolationException`,需单独处理

## 示例

```java
@RestController
@RequestMapping("/api/users")
public class UserController {

    @PostMapping
    public Result<User> create(@Valid @RequestBody UserDto dto) {
        if (userService.existsByEmail(dto.getEmail())) {
            throw new BizException(400, "邮箱已被注册");   // 业务校验抛异常,统一处理
        }
        return Result.ok(userService.create(dto));
    }
}
```

请求 `{"username":"a","email":"not-an-email"}` 会返回:

```json
{ "code": 400, "message": "用户名长度 2-20; 邮箱格式不正确", "data": null }
```

## 常见问题与坑

- **`@Valid` 不生效**:校验注解加在 DTO 字段上,Controller 参数忘了加 `@Valid`;或没引 `spring-boot-starter-validation`
- **`@NotBlank` 用在非字符串**:`@NotBlank` 只对字符串有效,Integer 用它报错,数字用 `@NotNull`
- **分组校验没指定组**:分组后 `@Valid` 不带组默认只校验「无组」的字段,用 `@Validated(组.class)`
- **兜底 `Exception` 吞堆栈**:一定要 `log.error` 记录,否则线上只看到「系统繁忙」无法排查
- **返回给前端的信息泄漏**:兜底异常别把数据库/堆栈细节返回给前端,记日志即可
- **校验注解的 `message` 不写**:默认英文报错对前端不友好,显式写中文 message
