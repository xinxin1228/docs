# 配置管理与多环境

## 概述

> 用 Profile 区分开发/测试/生产环境,用 `@ConfigurationProperties` 做类型安全配置绑定,并处理好外部化配置的优先级与敏感信息(不硬编码密钥)。这是后端工程化的基本功。

## 核心知识点

### Profile 多环境

按环境拆分配置文件,`application.yml` 里指定激活哪个:

```
application.yml              # 公共配置
application-dev.yml          # 开发环境
application-test.yml         # 测试环境
application-prod.yml         # 生产环境
```

```yaml
# application.yml
spring:
  profiles:
    active: dev          # 激活 dev,可被环境变量覆盖

# application-dev.yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/demo_dev
    username: root
    password: 123456

# application-prod.yml
spring:
  datasource:
    url: jdbc:mysql://prod-db:3306/demo
    username: ${DB_USERNAME}      # 生产密码来自环境变量,不写死在文件
    password: ${DB_PASSWORD}
```

激活方式(优先级从高到低):

```bash
# 1. 命令行参数
java -jar app.jar --spring.profiles.active=prod

# 2. 环境变量
export SPRING_PROFILES_ACTIVE=prod

# 3. yml 里的 spring.profiles.active
```

也可用 `@Profile` 让某个 Bean 只在特定环境生效:

```java
@Profile("dev")
@Bean
public DataSource mockDataSource() { ... }   // 仅 dev 环境注册
```

### 类型安全配置绑定

`@Value` 只适合取少量简单值,复杂配置用 `@ConfigurationProperties`:

```java
@Component
@ConfigurationProperties(prefix = "app")
public class AppProperties {
    private String name;
    private Upload upload = new Upload();

    public static class Upload {
        private String dir;
        private long maxSize;
        // getter/setter
    }
    // getter/setter
}
```

```yaml
app:
  name: demo
  upload:
    dir: /data/upload
    max-size: 10485760   # 松散绑定:max-size ↔ maxSize
```

配合 `@Validated` + 校验注解可在启动时校验配置合法性。

### 外部化配置优先级(Spring Boot 约定)

高 → 低:

1. 命令行参数 `--key=value`
2. 环境变量(`SPRING_APPLICATION_JSON` 等)
3. `application-{profile}.yml` / `application.yml`
4. 默认值

**规律:越「外部」越优先,生产可用环境变量覆盖文件里的默认值。**

### 敏感信息管理

```yaml
# ❌ 硬编码密钥,提交仓库即泄漏
password: my-secret-123

# ✅ 环境变量占位
password: ${DB_PASSWORD}

# ✅ 更进阶:配置中心 / Vault 动态获取
# Spring Cloud Config、Nacos、Vault
```

启动时注入:

```bash
export DB_PASSWORD='real-secret'
java -jar app.jar
# 或用 .env 文件 + dotenv,或 Docker Compose 的 environment
```

## 示例

```java
@ConfigurationProperties(prefix = "oss")
public record OssProperties(
    String endpoint,
    String accessKeyId,
    String accessKeySecret,
    String bucket
) {}

// 使用时注入,敏感值来自环境变量
@Bean
public OSSClient ossClient(OssProperties p) {
    return new OSSClientBuilder().build(
        p.endpoint(), p.accessKeyId(), p.accessKeySecret());
}
```

```yaml
oss:
  endpoint: ${OSS_ENDPOINT}
  access-key-id: ${OSS_ACCESS_KEY_ID}
  access-key-secret: ${OSS_ACCESS_KEY_SECRET}
  bucket: my-bucket
```

## 常见问题与坑

- **改配置不生效**:改了 yml 但没重启,或环境变量/命令行参数优先级更高覆盖了文件
- **密码硬编码进 yml 提交**:用环境变量注入,`.gitignore` 排除本地 `application-local.yml`
- **Profile 文件名拼错**:必须是 `application-{profile}.yml` 才被识别,`application.dev.yml` 不认
- **`@ConfigurationProperties` 不生效**:类没被 Spring 管理(缺 `@Component` 或没 `@EnableConfigurationProperties`);record 需用 `@EnableConfigurationProperties` 注册
- **`@Value` 拿不到**:属性名/前缀错,或对象里没有对应 getter
- **环境变量名映射**:`app.upload.max-size` → 环境变量 `APP_UPLOAD_MAXSIZE`,大小写/连字符易搞混,统一用 yml 占位符最稳
