# 并发编程

## 概述

> Java 并发编程:线程与线程池、`synchronized`/`Lock`/`volatile`、原子类与 CAS、JUC 工具类、`CompletableFuture`、虚拟线程。后端高并发接口、线程池参数调优、并发安全,都建立在这些基础之上。

## 核心知识点

### 线程的三种创建方式

```java
// 1. 继承 Thread
class MyThread extends Thread { public void run() {} }

// 2. 实现 Runnable(推荐,可传参、可复用)
Thread t = new Thread(() -> System.out.println("hi"));

// 3. 实现 Callable(有返回值、可抛异常)
FutureTask<Integer> ft = new FutureTask<>(() -> 42);
```

### 线程池(生产核心)

`ThreadPoolExecutor` 七大参数:

```java
new ThreadPoolExecutor(
    corePoolSize,       // 核心线程数
    maximumPoolSize,    // 最大线程数
    keepAliveTime,      // 空闲线程存活时间
    TimeUnit.SECONDS,
    workQueue,          // 任务队列
    threadFactory,      // 线程工厂(命名)
    rejectionHandler    // 拒绝策略
);
```

执行顺序:核心线程满 → 入队列 → 队列满 → 扩容到最大线程 → 仍满 → 拒绝策略(AbortPolicy 抛异常 / CallerRunsPolicy 调用方执行 / DiscardPolicy 丢弃)。

**参数怎么设**(经验值,IO 密集 vs CPU 密集):

```java
// IO 密集(大部分时间等 IO):线程数设大
int ioThreads = Runtime.getRuntime().availableProcessors() * 2;
// CPU 密集:核数 + 1
int cpuThreads = Runtime.getRuntime().availableProcessors() + 1;
```

**不要用 `Executors.newFixedThreadPool` 等快捷方法**:它们用的是无界队列 `LinkedBlockingQueue`,任务堆积会 OOM。推荐手动 `new ThreadPoolExecutor`,或用 Spring 的 `ThreadPoolTaskExecutor`。

### synchronized 与 Lock

```java
// synchronized:锁对象或方法,自动加锁释放
public synchronized void add() { count++; }
// 等价于
public void add() { synchronized (this) { count++; } }

// Lock:可中断、可超时、可公平
ReentrantLock lock = new ReentrantLock();
lock.lock();
try { count++; } finally { lock.unlock(); }
```

`synchronized` 简单够用就选它;需要「可中断获取锁、超时、多条件」时用 `Lock`。

### volatile 与可见性

`volatile` 保证变量的**可见性**和**禁止指令重排**,但**不保证原子性**:

```java
volatile boolean running = true;   // 一个线程改,其他线程立即可见
// running++ 依然不是原子的,别用 volatile 做计数
```

### 原子类与 CAS

`AtomicInteger` 等通过 CAS(Compare-And-Swap)无锁实现原子操作,性能优于 `synchronized`:

```java
AtomicInteger counter = new AtomicInteger();
counter.incrementAndGet();   // 原子自增
counter.compareAndSet(expect, update);
```

CAS 的 ABA 问题:可用 `AtomicStampedReference` 加版本号解决。

### JUC 工具类

```java
// CountDownLatch:等待 N 个任务完成
CountDownLatch latch = new CountDownLatch(3);
// ... 每个任务完成后 latch.countDown(); 主线程 latch.await();

// Semaphore:信号量,限流
Semaphore sem = new Semaphore(10);   // 最多 10 个并发
sem.acquire(); try { ... } finally { sem.release(); }

// CyclicBarrier:让一批线程到达同一屏障点再一起继续

// ThreadLocal:线程私有变量(如保存当前登录用户、请求上下文)
ThreadLocal<String> holder = new ThreadLocal<>();
holder.set("userId");
// 用完记得 holder.remove(),防止线程池复用导致串数据/内存泄漏
```

### CompletableFuture(异步编排)

```java
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> fetchUser())          // 异步执行
    .thenApply(u -> u.getName())             // 上一步结果转换
    .thenCompose(u -> fetchOrderAsync(u))    // 组合异步任务(拍平)
    .exceptionally(e -> "fallback");         // 异常兜底

// 并行等所有结果
CompletableFuture.allOf(f1, f2, f3).join();

// 阻塞拿结果
String result = future.get(3, TimeUnit.SECONDS);
```

### 虚拟线程(Java 21)

见《新特性》篇。IO 密集高并发下,虚拟线程是更轻量的替代方案,但注意别在虚拟线程里做长时间 CPU 计算或阻塞锁。

## 示例

```java
import java.util.concurrent.*;

public class ConcurrencyDemo {
    public static void main(String[] args) throws Exception {
        ThreadPoolExecutor pool = new ThreadPoolExecutor(
            4, 8, 60, TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(100),
            r -> new Thread(r, "worker-" + r.hashCode()),
            new ThreadPoolExecutor.CallerRunsPolicy());

        CountDownLatch latch = new CountDownLatch(10);
        AtomicInteger success = new AtomicInteger();
        for (int i = 0; i < 10; i++) {
            int id = i;
            pool.execute(() -> {
                try {
                    // 模拟调用远程接口
                    Thread.sleep(50);
                    success.incrementAndGet();
                } catch (InterruptedException ignored) {
                } finally {
                    latch.countDown();
                }
            });
        }
        latch.await(5, TimeUnit.SECONDS);
        pool.shutdown();
        System.out.println("成功 " + success.get() + " 个");
    }
}
```

## 常见问题与坑

- **用 `Executors` 无界队列**:任务积压 OOM,手动建池
- **`i++` 不是原子操作**:多线程共享变量要用 `AtomicInteger` 或加锁
- **`ThreadLocal` 忘 remove**:线程池复用线程导致数据错乱/内存泄漏
- **共享可变对象**:多个线程改同一个 `ArrayList`/`HashMap` 会踩并发修改,用并发容器或锁
- **锁粒度**:锁的范围尽量小,锁里别做 IO
- **`synchronized` 锁了可变对象**:锁对象不能变,最好锁 `final` 对象或类
